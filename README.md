# token-killer · 解题实验室

**哪种玩法能在十分钟内得到最多有效 token？多个完整窗口又能累计多少？** 在自己的电脑上试跑方格子容纳、四境驿站、Cap Set、Golomb 尺或超维递归模拟器，分别提交模型回执和数学裁判成绩。[English quick start](README.en.md) · [玩法挑战与提交指南](CONTRIBUTING.md)

主控台默认单路、10 分钟。选玩法、时长后即可开始，运行时能看到有效速度、本场累计和剩余时间，也可随时停止。40 路须手动选择。点击「刷新」可查看当前账号实际返回的套餐窗口、剩余百分比和重置时间。只有官方读数明确允许普通套餐且每个适用窗口都有余量时，实跑才会开始。额度未知或受限会停止发起新请求，已经返回的回执会保留。本机解题和复验可独立使用。

## 启动

**按有效 token 定量运行。** 在「执行客户端」选择 **OpenAI · ChatGPT**，选择玩法与时长上限，填写有效 token 目标，例如 `100000`。页面按完整回执更新累计值、最近 60 秒的速度、进度和预计剩余时间。达到目标或时长上限即停止派发，在途回执可能令总量超过目标。

**从 Codex、Claude Code 或 Google Antigravity 接手。** 完成一次 MCP 配置，在网页选择客户端、方格或四境、最多轮数，点击「创建 MCP 对局」，把接手指令粘贴到对应客户端。可记录真实逐轮用量的客户端也能按 token 目标运行；缺少用量时，留空目标即可按轮数推进并查看每分钟裁判轮数。客户端自报用量单列，个人成绩与回执默认保存在本机。[三客户端接入指南](CLIENTS.md)

下载源码或 ZIP 并解压到可写目录。安装 Python 3.10+，在项目目录启动。离线玩、离线演练和本地裁判只用 Python 标准库。

| 平台 | 启动游戏 |
|---|---|
| Windows | 双击 [启动解题实验室.cmd](启动解题实验室.cmd)，或运行 `py -3 -B -X utf8 lab.py` |
| macOS | 在终端运行 `sh start.sh --open` |
| Linux 桌面 | 运行 `sh start.sh --open` |
| 无桌面环境 | 运行 `python3 -B -X utf8 lab.py`，用同台机器的浏览器访问打印的地址 |

启动后打开终端给出的本机地址。进入任一游戏，或点「离线演练」体验两款游戏的对照。按 Ctrl+C 结束。默认存档位于项目中的 SQLite 文件，报告位于 `验收/`。工作目录和临时目录所在磁盘需至少有 20 GiB 空余。服务仅监听本机回环地址。

实验室、方格轻量版和四境驿站均可切换中文或 English。从实验室进入游戏时会带上当前语言。模型原文与裁判回执保留原始语言。

- **方格子容纳**可以试摆 26 个单位正方形，实时回看碰撞和裁判结果。完整方格网页还支持多个块数和经验证的成果楼。
- **四十九站覆盖**用 26 份名单覆盖 49 站之间的 1,176 个无序站点对。
- **离线演练**用同一套裁判验证单局、同游戏双局和跨游戏并发的工作流。

## 用订阅参加吞吐挑战

先按下文安装可选依赖。在实验室展开「连接 ChatGPT 订阅」，通过官方页面授权，并在官方设置中限制应用可用的套餐额度、关闭充值余额使用，再回实验室确认。十分钟实跑会尝试记录共享账户周额度和逐轮模型用量；账户读数不可用时留空。有效 token 取非缓存输入加输出，账户周额度按平台口径单列。[官方说明](https://help.openai.com/en/articles/20001542-using-your-chatgpt-plan-in-other-apps-and-sites)

有两种计分方式，报告中分栏记录，不能把它们混成一个数：

| 赛制 | 时间和算法 | 记录内容 |
|---|---|---|
| **速度赛** | 一个完整的 600 秒窗口；有效 Token 总量 ÷ 10，得到有效 Token/分钟。有效 Token = 非缓存输入 + 输出。 | 十个一分钟窗口、唯一完整回包数、速度，以及单独列出的数学成绩。 |
| **累计总量赛** | 总时长可变；只把不重叠的完整 600 秒窗口纳入总量。按唯一回包 ID 去重，每份回包至多计一次；注明总运行时长。 | 完整窗口数、每窗及总有效 Token、去重回包数和数学成绩。未满 600 秒的尾段另列，不并入完整窗总量。 |

混合冲榜同时运行 26 块方格与 49 站接力，单次 10 分钟，单独保留本机报告。「开始三组对照」依次测试单局、同题双路和混合双路，每组 10 分钟。并发时，各路分别接收候选与裁判反馈。网页显示计时进度、预计剩余时间、每分钟有效 token 和累计用量。速度赛以 600 秒内有效 Token 总量除以 10 计分。
默认冲榜入口根据该玩法已完成的实测，在开跑前显示预计时间与有效 token。运行中的估算使用已收到的回执。

「连续冲榜」固定启动时的推荐玩法，每组十分钟。每组结算后单独归档，再从当时项目最佳存档开始下一组。网页累计完整回包、有效 token 和已入库的新纪录。点击「停止」或本轮收到平台错误即结束连续运行。本机 API 的 `POST /api/lab/continuous` 可选传入 `{"windows": 2}`，在完成指定窗口数后结束。
重启实验室后仍可查看最近的连续冲榜记录。中途退出时，历史会复算已落盘且可确认在窗内的回执；之后点击连续冲榜会从最新存档开始新会话。
在「开始并发对照」旁选择并发路数或题目配比。每次从验算过的存档开始，两组各跑 10 分钟。报告记录所有通道的模型请求同时在途的时长，并按同样的 token 和有效候选口径排名。提前结束的场次在网页上按实际运行时长显示速率。冲榜入口在首次实测前使用双路，后续使用历次完整并发对照中已验证最快的玩法。
「单题方格与多题组合」保持八条接力通道。单题组的八条方格通道都跑 26 块，多题组分别用两条通道跑 26、37、41 和 50 块。两个窗口使用共同题包的同一起始存档。报告逐题展示去重候选数。
「多题十六路与二十四路」固定上述四种方格和接力的起点和比例。每道方格题的通道从两条增至三条，接力从八条增至十二条。两组各跑十分钟。
「多题十六路与全接力」把十六条接力通道和八条接力加八条方格通道放在同一套十分钟规则下比较。接力使用同一个已验算的起始存档。
全接力并发对照支持十六、二十、二十二、二十三和二十四路的分组比较。每次对照都使用同一个接力起始存档，先跑较高并发，每组十分钟。
二十二路单目标与双目标对照固定并发和起始存档。双目标每轮让模型挑两个不同的缺口，从同一父档分别试修，由原生裁判比较覆盖。报告中的去重候选只统计每轮最终提交的方案。
模型可以直接提交新解，也可以选择方格搜索方向或从当前缺口选一个站对，让现有本机求解器试算。回执保留请求、搜索和复算，各段的耗时与实际候选分别显示。方格通道会画出最新通过几何裁判的试摆。并发组只有记录到请求区间重叠，才参与吞吐排名。
严格刷新项目最佳的候选经复算后进入游戏存档和项目成绩页。成果楼使用各已存档方格题与接力当前最佳成绩的存档链，每层对应一次严格提分。

每次对照和冲榜都把起始解、每轮原始候选、裁判回执和汇总保存在本机 `验收/吞吐对照-…`。需要复算累计总量赛时，将连续、互不重叠的完整窗口目录依时间顺序传给 `--series`：

```sh
python -B benchmark_proof.py --series <first-window-dir> <second-window-dir>
```

每个目录对应一个完整 600 秒窗口；命令复算汇总时会按唯一回包去重。保留窗口目录和总时长，以便他人理解结果。速度赛仍可用单窗口复验命令。

对照中断后可点「继续实跑」。跑满十分钟且通过计量和并发核对的组继续使用原回执。中断或未通过核对的组归档到 `attempts/`，再用原始局面开始新的十分钟。混合冲榜每次从当前最佳成绩开始。吞吐只累计窗口内收到完整模型回包的 token。单路响应提前结束时，其他通道继续计时，受影响的窗口保留回执和中断记录并退出完整窗口排名。计时截止后才观察到的连接错误会记为窗口外事件。套餐或授权错误会停止整组。

## 项目成绩

实验室的「项目成绩」从本地裁判存档重验每关最好分数。静态版适合托管，访客可下载完整坐标或覆盖名单。项目起点与公开数学资料在表里分别链接。

```powershell
python -B scoreboard.py export
python -B scoreboard.py verify public/leaderboard.json
```

打开实验室右上角的「项目成绩」即可查看自己的最佳解。静态导出由操作者在本地执行。

### 本地复验包

需要制作个人复验包时，先执行上面的成绩导出，再运行 `python -B release.py --public-verifier --out public/verifier.zip` 生成校验器。随后用 `release.py --out <个人复验包.zip> --evidence-run <完整对照目录>` 打包窗口回执和当前成绩。解压后运行以下命令。也可打开「复验」里的成绩页。

```powershell
python -B benchmark_proof.py 复验/吞吐回执.json
python -B scoreboard.py verify 复验/leaderboard.json
```

吞吐复算检查窗口、计量、并发和候选得分。模型计数来自导出的本地回执，平台账单和未完成回包的用量需另查平台记录。

### 方格与四境玩法

**方格装箱**让模型搜索单位方块的坐标布局。玩家可尝试移动、旋转或选择搜索分支；本机几何裁判检查越界和重叠，成绩看有效布局和更小的外框。**四境驿站**用名单覆盖 49 个站之间的 1,176 个无序站点对；玩家提出换站或接力分支，本机裁判重算合法名单、覆盖对数和最佳分数。吞吐成绩与数学成绩分开报告：速度提升不代表解更好，解变好也不代表速度达标。

欢迎有仓库访问权限的协作者提交方法、未奏效的负结果，以及经过整理的回执汇总。请勿附上用户私下档案、私人跑分、个人/账户/任务 ID、quota 读数或绝对路径；原始请求、模型回复、私人材料及完整授权信息留在本机。分享前确认材料有公开权限；保留原文和许可边界，只提供获准共享的摘要或可复现样例。

[有仓库访问权限的协作者：提交玩法方法、负结果或实测汇总](https://github.com/g6759/token-killer/issues/new?template=throughput-method.yml)

## 新研究题

研究题使用独立的数学裁判、题包和正式场景。它们的游戏分数不等于吞吐赛成绩；已有速度或累计 Token 记录来自原先的方格/四境驱动，不能直接当作这些新题的实测速度。每个题包都有独立单路正式场景，场景 ID 与题包 ID 相同。

| 题包 | 玩家目标 | 单路正式场景 |
|---|---|---|
| `cap-set` | 在四维三元空间寻找更大的无三点共线点集。坐标是 0、1、2；不允许三点满足逐坐标模 3 的和为 0。 | `/research?game=cap-set` |
| `golomb-ruler` | 用 8 个刻度构造差值互异的尺，并缩短首尾长度。镜像尺视作同一解。 | `/research?game=golomb-ruler` |
| `lorenz-divergence` | 调整初始值，寻找两条 Lorenz 轨迹首次达到分离阈值的时刻；数值裁判会作独立方法复核。 | `/research?game=lorenz-divergence` |

同一裁判规则还提供 `cap-set-5d`、`cap-set-6d`、`cap-set-7d`、`cap-set-8d`，以及 `golomb-ruler-12`、`golomb-ruler-16`。对应入口分别使用同名 `game` 参数，例如 `./research?game=cap-set-8d`。8 维页面可选载入历史 401 点构造作参照；它是已复核的历史构造，不代表文献首创或最优。玩家提交的新构造与历史参考分开标记。

## Codex MCP

离线玩法和成绩复核只依赖 Python。使用 ChatGPT 订阅授权或 MCP 前，在项目根目录安装可选依赖：

| 平台 | 创建环境 | 安装依赖 |
|---|---|---|
| Windows | `py -3 -m venv .venv` | `.venv\Scripts\python.exe -m pip install -r requirements.txt` |
| macOS / Linux | `python3 -m venv .venv` | `.venv/bin/python -m pip install -r requirements.txt` |

启动脚本会优先使用项目的虚拟环境。在 Codex 中打开项目根目录，将 [MCP 示例](mcp.config.example.toml) 合并到项目的 `.codex/config.toml`，按照示例将解释器和服务器路径改为本机绝对路径。重启 MCP 会话后，用 `game_status` 读取游戏状态。

连接订阅时，Windows 使用 DPAPI 保护凭据，macOS 使用系统钥匙串，Linux 桌面会话需要可用的 Secret Service。离线游戏可直接启动。
